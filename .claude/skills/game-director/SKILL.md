# Game Director Workflow

1. Read the product spec and current build status.
2. Inspect the actual code before recommending changes.
3. Identify the smallest complete vertical slice that advances the campaign.
4. Keep the MVP limited to three missions, complete screens, one simulation loop, and the required scientific data.
5. Preserve the premium coloured 2D ASCII terrain treatment as a core identity requirement. It is not a stretch feature. Reject spectacle that harms map readability or gameplay.
6. Reject scope that adds visual spectacle without improving clarity, choices, feedback, or mission meaning.
7. Define acceptance criteria before coding.
8. Never start more than one milestone per approval.
9. After implementation, report what is now playable and what remains unverified.

When two design options are both viable, choose the one with lower integration risk and better playability, not the one with more features.
